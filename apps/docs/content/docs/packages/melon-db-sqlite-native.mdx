**Status:** Shipped (sync JSI + TurboModule fallback) · **Expo Go:** Not supported

Native SQLite module used by [`@melon/db-sqlite/rn`](/docs/packages/melon-db-sqlite). For Expo Go, use [`@melon/db-sqlite/expo`](/docs/packages/melon-db-sqlite) instead.

## Install (alpha)

```bash
npm install @melon/db-sqlite-native@alpha
```

Or with Bun:

```bash
bun add @melon/db-sqlite-native@alpha
```

## Platform support

| Platform | Binding | Status |
|----------|---------|--------|
| iOS (dev build) | Sync C++ JSI (`global.melonSqliteJsi`) | Supported |
| iOS (dev build) | TurboModule fallback (`mode: 'turbo'`) | Supported |
| Android (dev build) | Sync C++ JSI (`global.melonSqliteJsi`) | Supported |
| Android (dev build) | TurboModule fallback (`mode: 'turbo'`) | Supported |
| Expo Go | N/A | Not available |

## Limitations

- **BLOB / `bytes` fields** are not round-tripped (returned as `null`).
- Reactive invalidation is handled by `@melon/db-sqlite` `observeQuery` (predicate-aware; same on native and Expo paths).

## Setup

- **Expo Go:** [`apps/playground-rn`](/docs/getting-started) — `bun run dev:rn`
- **Development build (iOS):** `bun run dev:rn:dev` then `bun run dev:rn:dev:start` — expect `native jsi-sync (ios)` badge
- **Development build (Android):** `bun run dev:rn:dev:android` then start Metro — expect `native jsi-sync (android)` badge

Pass `basePath` (e.g. `expo-file-system` `documentDirectory`) when using a relative `filename`.

`createJsiSqliteAdapter({ mode: 'auto' })` prefers sync JSI on iOS and Android when the host object is installed. Set `EXPO_PUBLIC_MELON_SQLITE=turbo` to force the async TurboModule path for comparison.

After changing native spec or C++ sources, run `expo prebuild --clean` in `apps/playground-rn-dev`. See the [package README](https://github.com/nwnichols02/melon/blob/main/packages/melon-db-sqlite-native/README.md).
