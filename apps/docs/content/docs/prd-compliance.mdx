This page tracks how Melon implementation compares to the product requirements in `.cursor/rules/` (prd-1 through prd-3, db-core, db-query, db-prisma, package-roles, file-layout). For shipped phase history see [Roadmap](/docs/roadmap).

**Legend:** **Done** · **Partial** · **Deferred** (intentional v1 limit) · **Gap** (not scheduled / needs decision)

---

## Executive summary

| Bucket | Examples |
|--------|----------|
| **Done** | Core engine, SQLite (Node/Bun/Expo/native), sync pull/push, codemods, devtools, RN benchmarks |
| **Partial** | Mango/Prisma surfaces, testkit helpers, hook ergonomics |
| **Deferred** | SQL joins, `hasMany` includes, `Q.on`, full schema codemods, background sync |
| **Gap** | `getChangedCollections`, `useRecord`, Supabase/REST backends, `playground-web` |

## Phase 29+ decisions

Product decisions recorded here (not blockers for phases 0–28):

| Item | Decision | Rationale |
|------|----------|-----------|
| `getChangedCollections` | **Defer** | Sync uses outbox + `getLocalChanges`; adapter hook when sync needs incremental adapter scans |
| SQL JOIN / `hasMany` / `Q.on` | **Defer** | Documented v1 limits on [Roadmap](/docs/roadmap) |
| Sync `merging` state | **Defer** | Apply path is synchronous; add when merge UI needs distinct phase |
| `@melon/db-react` → `@melon/sync` dep | **Accept** | DX for `useSync`; split only if publishing react without sync |
| `playground-web` | **Defer** | No web adapter package yet |
| Read-during-write blocking | **Defer** | Serialized writes sufficient for v1; revisit if readers observe torn state |
